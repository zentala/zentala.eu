What the analysis system should actually produce

This page shows the practical output shapes that improve agent grounding and developer experience: normalized snapshots, findings, work queues, file analysis, and snapshot comparisons.

Why this matters

  • Agents stop guessing which files are central or stale.
  • Developers get ranked work instead of raw tool noise.
  • Refactors become easier to justify and verify.
  • Architecture health becomes discussable with evidence.

How this helps agents

  • Start from `get_latest_snapshot` instead of reading files blindly.
  • Use `get_hotspots` to focus review and planning.
  • Use `get_file_analysis(path)` before touching critical modules.
  • Use `compare_snapshots` to explain whether a change improved structure.

How this helps developers

  • Faster triage of refactor and cleanup work.
  • Clearer evidence for architecture decisions.
  • Better onboarding for new contributors.
  • A shared language for risk, confidence, and value.

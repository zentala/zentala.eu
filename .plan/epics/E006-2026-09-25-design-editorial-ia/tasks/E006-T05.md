## Steps

1. `src/content/config.ts`: apply IA §2.3 exactly. Export `LAYERS` and `KINDS`. Add optional `layer`, `kind`, `order`, and `concepts: z.array(reference('glossary')).default([])` to `docsSchema`. Add `related: z.array(z.string()).optional()` and `provenance: z.enum(['dictated','researched','proposed']).optional()` (DESIGN.md "Proposed additions"). Keep `tags` and `customSlug` in `baseSchema` for now (E006-T12 removes them). Add the `glossary` collection with the §2.3 schema, with one deviation: `definition` is optional and a `superRefine` requires it when `status === 'defined'` (a `needs-definition` entry has no definition text, §7).
2. `src/content/glossary/<slug>.md` for each of the 19 rows of IA §3: `term`, `aliases`, `definition` (40–280 chars, lifted or tightly paraphrased from the cited file:line — read every citation; invent nothing), `href`, `related`, `status`, `autolink` (true only for the §7 list), `source` for the external entry. The four `needs-definition` rows ship without a definition and carry `<!-- ASK-n -->` in the body asking Paweł for one sentence. Body = optional long form for the `/glossary` page.
3. Frontmatter sweep: for every chapter with a row in §2.5, set `layer`, `kind`, `order`; map `tags` → `concepts` per §3 rule 5 (keyword tags are dropped); delete the `tags` field from those files. Held stubs (draft) get the same treatment. Do not edit bodies.
4. `just build` green; commit.
